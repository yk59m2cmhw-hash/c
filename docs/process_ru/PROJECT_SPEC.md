# PROJECT_SPEC — Smog Tomorrow? (Алматы)

_Зафиксировано 15.11.2026 ~13:25 Алматы, ДО обучения и настройки моделей._

## 1. Название, трек, формула
- Рабочее название: **Smog Tomorrow? — a day-ahead PM2.5 warning for Almaty** («Смог завтра?»).
- Трек: **AI + Climate** (brief §4.3; основа — suggested project 4.3.2 «Next-day air quality forecast» + своё).
- Формула: помогаем **учителю физкультуры алматинской школы** получить **прогноз PM2.5 на завтра и решение «урок на улице / в зале»** из **сегодняшних измерений воздуха и прогноза погоды**, каждый вечер в 18:00.

## 2. Основной сценарий и критерии готовности
Вечером в 18:00 пользователь открывает инструмент → видит прогноз среднесуточного PM2.5 на завтра, категорию, диапазон неопределённости, рекомендацию и три главные причины.
Готово, если:
1. Ноутбук выполняется сверху вниз без ошибок на чистой машине из файлов репозитория (без ключей и секретов).
2. В одной таблице стоят рядом: persistence, климатология, наша модель — на отложенном тестовом периоде.
3. Для порога «вредно» раздельно посчитаны пропуски и ложные тревоги.
4. Показаны минимум 3 конкретных дня, где модель ошиблась, с объяснением.
5. Демо: выбор даты из тестового периода → прогноз, сделанный «накануне», и что было на самом деле.

## 3. P0 (обязательно)
- Данные: PM2.5 (OpenAQ, станция 8876, почасовые) + погода (Open-Meteo: ECMWF IFS 9 км, город и горная ячейка; ERA5 — высота слоя перемешивания).
- Признаки, baseline, модель, оценка по протоколу §6.
- Интервал неопределённости из ошибок на валидации.
- Разбор ошибок; ограничения.
- Ноутбук с сохранёнными выводами, README (write-up по шаблону brief), Sources/credits, демо.
- STATUS.md, русское объяснение для участника, шпаргалка Q&A, сценарий видео.

## 4. P1 (максимум одно улучшение, только после работающего P0)
- **Проверка на настоящем прогнозе погоды «за день до»** (Open-Meteo Previous Runs API) для тестового периода: насколько падает качество, когда погода на завтра не «известна», а предсказана. Если API недоступен — честно написать, что не проверено.

## 5. Сознательно НЕ входит
Аккаунты, мобильное приложение, карта города, несколько станций, почасовой прогноз, уведомления, LLM-чат, обучение нейросетей, другие города, «живой» режим на сегодняшних данных (станция перестала передавать данные 14.11.2025 — это ограничение будет указано).

## 6. Протокол оценки (зафиксирован до настройки)
**Цель (target):** среднее PM2.5 за календарные сутки D+1 по местному времени Алматы; день валиден при ≥18 часовых значениях.
**Момент прогноза:** 18:00 местного времени дня D. Из измерений PM2.5 можно использовать только часы до 18:00 дня D.
**Погода на завтра:** суточные агрегаты за день D+1 из ECMWF IFS 9 км (анализ + краткосрочный прогноз). Это «почти идеальный прогноз погоды» — допущение, которое проверяется в P1.
**Разбиение по дате цели (хронологически, без перемешивания):**
- Train: по 30.09.2023
- Validation (выбор модели, гиперпараметров, порогов): 01.10.2023 – 30.09.2024
- Test (не используется до финального запуска): 01.10.2024 – 13.11.2025
- Финальная модель: переобучение на Train+Validation с выбранными настройками → один запуск на Test.
**Baselines (не ослаблять):**
- B0 persistence: завтра = среднее за последние 24 часа (на 18:00). Дополнительно для справки — «календарный» вариант (завтра = полные сутки сегодня), у которого информации на 6 часов больше, чем у нас.
- B1 климатология: среднее по месяцу из обучающих лет.
**Модели-кандидаты:** Ridge-регрессия на log(1+PM) (простая, объяснимая) и градиентный бустинг (небольшие деревья). Если бустинг не даёт заметного выигрыша на Validation, берём Ridge.
**Группы признаков (абляция на Validation):** (a) только история PM; (b) + погода в городе; (c) + инверсия (температура в горах минус в городе); (d) + высота слоя перемешивания.
**Метрики:**
- Основная: MAE (µg/m³) на тестовых днях отопительного сезона (октябрь–март); дополнительно — все дни теста. Skill = 1 − MAE_модели / MAE_persistence. Бутстреп-интервал для разницы.
- Тревога «завтра > 35,4 µg/m³» (граница US EPA «Unhealthy for Sensitive Groups»): попадания, пропуски, ложные тревоги, precision/recall. Порог срабатывания по прогнозу подбирается на Validation по цене ошибки «пропуск = 2 × ложная тревога» — одинаково для модели и для persistence.
- Начало эпизода: день > 35,4 после «чистых» последних 24 часов (≤ 35,4). Доля пойманных начал — отдельно.
- Покрытие интервала неопределённости на Test.
**Честность:** все числа в README — из сохранённого запуска ноутбука. Ранний разведочный просмотр корреляций (до фиксации протокола) был сделан на всех годах, включая тестовый период; по его результатам признаки не отбирались (набор задан физикой: инверсия, ветер, осадки, перемешивание). Это будет указано в write-up.

## Поправки к спецификации (в порядке появления)
1. **До обучения:** признак «высота слоя перемешивания» исключён — в публичном архиве пропуск 01.01–30.06.2024.
2. **До теста:** выбор модели сделан по двум прошлым зимам (2022/23 и 2023/24), а не по одной; правило «проще, если сложная не лучше на 5 %».
3. **До теста:** вероятный диапазон считается отдельно для октября–марта и апреля–сентября.
4. **Тест прогноза выполнен один раз** 15.11.2026 в 08:38 UTC. Повторные сборки ноутбука дают те же числа (сверено по `metrics.json`).
5. **После теста, по запросу участника:** добавлен раздел «расписание» (второе улучшение сверх P1). Правило без подгоночных чисел, сначала опробовано на проверочном году, затем один раз запущено на тесте. Модель прогноза не менялась.

## Объединение версий (сессия 3, 15.11.2026 ~20:30 Алматы)
В репозитории было две версии проекта от двух сессий. Финальная работа = эта версия (прогноз с погодой на завтра + расписание) как база; из первой версии взят файл глобальной модели CAMS для дополнительного сравнения. Код первой версии остался в истории ветки. Модель прогноза и её настройки при объединении **не менялись**.

6. **После теста, описательно (модель не меняется; результат публикуем любым):**
   - *Глобальная модель CAMS* как ещё один baseline на том же тестовом периоде: MAE, смещение, тревоги по простому правилу (CAMS > 35,4) и с порогом, подобранным на проверочном году по тому же правилу цены, что у persistence.
   - *Школьные часы*: те же предупреждения пересчитываются по среднему PM2.5 за 08:00–18:00 дня D+1 (нужно ≥ 6 из 10 часов), потому что урок идёт днём, а цель модели — сутки.

7. **Внешняя проверка на 2026 годе — протокол записан ДО расчёта** (этот текст закоммичен раньше, чем посчитано хоть одно число на новых данных; до этого были просмотрены только три строки сырого файла датчика):
   - **Данные:** гражданский датчик sensor.community SDS011 № 78340 (центр Алматы). Он был выбран первой сессией как единственный кандидат до каких-либо расчётов. Период: с первого дня в архиве (15.01.2026) по 14.11.2026. Очистка — как в `scripts/fetch_citizen_sensor.py`: час = среднее показаний, нужно ≥ 6 показаний; отбрасываются значения < 0 и > 2000; никаких поправок на влажность и калибровку.
   - **Цель и входы:** те же определения, что в основном протоколе (§6): среднее за календарные сутки D+1 по этому же датчику (≥ 18 часов); входы PM — по этому датчику до 18:00 дня D. Погода на завтра — **настоящий архивный прогноз**: основной вариант «прогноз двухдневной давности» (заведомо существовал в 18:00), дополнительный — «однодневной давности».
   - **Модель:** замороженная (обучена на эталонном мониторе по 30.09.2024). Без переобучения, без пересчёта шкалы датчика. Пороги тревоги те же (модель 32,5; persistence 29,5), диапазон тот же.
   - **Сравнение:** persistence (последние 24 ч на 18:00) по тому же датчику; дополнительно CAMS.
   - **Метрики:** главная — MAE в октябре–марте против persistence, с 95 % интервалом выигрыша (бутстреп неделями); также MAE по всем дням, тревоги (поймано / пропущено / ложные), начала смога, покрытие диапазона, расписание (2 урока в неделю) на полных школьных неделях октября–марта.
   - **Заранее известные оговорки:** SDS011 — дешёвый оптический датчик, завышает в сыром воздухе; он стоит в другой точке города; уровень 35,4 на его шкале не равен уровню эталонного монитора. Поэтому главная метрика — ошибка относительно persistence на том же датчике, а счёт тревог вторичен.
   - **Правило отчёта:** запуск один; публикуются все числа, какими бы они ни были. Если интервал выигрыша включает 0 — пишем «перенос не доказан». Если после просмотра придётся чинить ошибку в коде — это будет указано.

8. **Итог внешней проверки (запуск один, 15.11.2026 ~20:45 Алматы) и что из этого следует.** Замороженная модель на гражданском датчике **не обошла persistence**: MAE в октябре–марте 9,9 против 7,5 µg/m³ (хуже на 2,4; 95 % интервал 1,3–3,4), по всем дням 6,1 против 4,5. Это публикуется как есть. Уточнение к протоколу: правило было «с первого дня в архиве»; в скобках был указан 15.01.2026, но архив начинается с 01.01.2026 — использованы все дни, результат «только с 15 января» напечатан рядом (модель 9,7, persistence 7,1). Расписание при этом осталось полезным (на 2,6 чище фиксированного, интервал 0,2–5,2; 15 недель).

9. **Проверка гипотезы «дело в сдвиге уровня» — записано ДО расчёта.** Этот шаг придуман после того, как стали известны итоговые числа п. 8 за весь 2026 год; ни одно число отдельно за октябрь–ноябрь 2026 ещё не смотрели, смещение прогноза и корреляции тоже не считали.
   - **Гипотеза:** модель запомнила уровень своего монитора; на датчике с другим уровнем показаний она ошибается на постоянный множитель.
   - **Метод («калибровка одним числом»):** c = средняя разность log(1+факт) − log(1+прогноз) по вечерам с датой ответа 03.01–31.03.2026 (первые месяцы с этим датчиком). Исправленный прогноз = exp(log(1+прогноз) + c) − 1. Больше ничего не меняется: ни веса модели, ни погода (прогноз двухдневной давности).
   - **Оценка:** дни ответа 01.10–14.11.2026 (начало следующего отопительного сезона; в подборе c не участвуют). Главное число — MAE исправленного прогноза против persistence на том же датчике, с 95 % интервалом выигрыша (бутстреп неделями). Рядом — неисправленная модель. Дополнительно — все дни после 31.03.2026.
   - **Правило отчёта:** один запуск, публикуем любой исход; если интервал включает 0 — «не доказано». Это проверка объяснения ошибки, а не новая версия продукта: рабочая модель остаётся замороженной.
